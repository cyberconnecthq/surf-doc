## Sample Queries

### 1. Weekly active addresses and tx count

```sql
SELECT toStartOfWeek(block_date) AS week,
       sum(tx_count) AS txs,
       sum(active_senders) AS senders
FROM agent.ethereum_chain_daily WHERE block_date >= today() - 90 GROUP BY week ORDER BY week
```

### 2. Daily gas and contract deployments

```sql
SELECT block_date, avg_gas_price_gwei, contract_deployments FROM agent.ethereum_chain_daily WHERE block_date >= today() - 30 ORDER BY block_date
```

### 3. Tempo daily activity overview

```sql
SELECT block_date, tx_count, active_senders, contract_deployments FROM agent.tempo_chain_daily ORDER BY block_date DESC LIMIT 30
```

### 4. Stablecoin supply trends on Tempo

```sql
SELECT block_date, symbol, supply FROM agent.tempo_stablecoin_supply ORDER BY block_date DESC, supply DESC LIMIT 50
```

### 5. Robinhood activity around public launch

```sql
SELECT date, blocks, transactions, successful_transactions,
       failed_transactions, unique_active_addresses
FROM agent.robinhood_chain_daily WHERE date >= toDate('2026-06-15') ORDER BY date
```

## Table Schemas

### `agent.ethereum_chain_daily`

Daily chain-level activity metrics in the style of Artemis ez_metrics. Transaction counts, active addresses (HLL approximate), gas usage, native value transferred, and contract deployments.

**Engine**: MergeTree | **Partition**: `toYYYYMM(block_date)` | **ORDER BY**: `block_date`

| Column | Type | Description |
|--------|------|-------------|
| `block_date` | `Date` | Partition key. One row per day. |
| `tx_count` | `UInt64` | Total transactions (including failed). |
| `successful_tx_count` | `UInt64` | Transactions with receipt_status = 1. |
| `active_senders` | `UInt64` | Approximate unique from_address count (HLL, ~2% error). |
| `active_receivers` | `UInt64` | Approximate unique to_address count (HLL, ~2% error). |
| `total_gas_used` | `UInt64` | Sum of receipt_gas_used across all transactions. |
| `avg_gas_price_gwei` | `Float64` | Mean receipt_effective_gas_price / 1e9. |
| `total_native_transferred` | `Float64` | Sum of transaction value in native units (ETH/BNB). Float64. |
| `contract_deployments` | `UInt64` | Count of transactions that deployed a new contract. |

<Tip>

- active_senders and active_receivers use HLL (uniq) — approximately 2% error margin
- avg_gas_price_gwei is the mean effective gas price in Gwei — not a median or percentile
- total_native_transferred is in native units (ETH/BNB), not USD
- contract_deployments counts transactions where receipt_contract_address is non-empty

</Tip>

<Warning>

- HLL-based active_senders/receivers are ~2% approximate — not exact unique counts
- Does not distinguish EOA vs contract senders
- No USD valuation of native transfers — join with prices table manually
- L2 gas pricing may not reflect actual user cost (excludes L1 data fees)

</Warning>

### `agent.robinhood_chain_daily`

Daily Robinhood Chain activity for complete UTC days, including blocks, transaction outcomes, unique active addresses, gas usage, and raw fees. History includes the pre-public-launch mainnet period.

**Engine**: MergeTree | **Partition**: `toYYYYMM(date)` | **ORDER BY**: `date`

| Column | Type | Description |
|--------|------|-------------|
| `date` | `Date` | Complete UTC calendar date. |
| `blocks` | `UInt64` | Number of canonical blocks for the complete UTC day. |
| `transactions` | `UInt64` | Total transactions included in those blocks. |
| `successful_transactions` | `UInt64` |  |
| `failed_transactions` | `UInt64` |  |
| `unique_active_addresses` | `UInt64` | Unique addresses participating in daily transactions. |
| `gas_used` | `UInt256` |  |
| `fees_raw` | `UInt256` | Raw gas fees without decimal or USD conversion. |

<Tip>

- Only complete UTC days are published; the current partial day is intentionally absent
- July 1, 2026 is the public-launch boundary, not the canonical-history start
- fees_raw is denominated in raw wei-like gas-fee units

</Tip>

<Warning>

- Current partial UTC day is excluded
- No token-transfer, DEX-volume, or USD fee metrics
- Pre-July 1 rows describe pre-public-launch mainnet activity

</Warning>

### `agent.robinhood_dataset_coverage`

Authoritative coverage contract for Robinhood analyst-facing datasets. Reports block-0 origin, contiguous complete-through bounds, raw live tip, internal gaps, and semantic limitations for each audited dataset.

**Engine**: View

| Column | Type | Description |
|--------|------|-------------|
| `dataset` | `String` | Audited internal dataset represented by this coverage row. |
| `coverage_state` | `String` | historically_complete, bounded_backfill, or live_only. |
| `first_covered_block` | `Nullable(UInt64)` | Start of the first contiguous audited range. |
| `first_covered_date` | `Nullable(Date)` |  |
| `complete_through_block` | `Nullable(UInt64)` | End of the first contiguous audited range starting at first_covered_block. |
| `complete_through_date` | `Nullable(Date)` |  |
| `raw_live_tip` | `Nullable(UInt64)` | Latest complete finalized raw-ingestion block used for comparison. |
| `internal_gaps` | `Nullable(UInt32)` | Number of gaps between audited range segments. |
| `semantic_coverage` | `String` | Dataset-specific inclusion boundary or limitation. |
| `observed_at` | `DateTime` | Time the coverage view was evaluated. |

<Tip>

- Check coverage_state='historically_complete' and internal_gaps=0 before claiming complete history
- Use semantic_coverage to preserve dataset-specific limits such as event-only transfers or mapped-pool DEX coverage
- Event-row minima are not coverage boundaries because valid block ranges may contain zero matching events

</Tip>

<Warning>

- Coverage rows describe audited range completeness, not row-level event density
- A historically_complete state remains subject to semantic_coverage
- Prices and token-metadata snapshot history are not certified by this coverage contract

</Warning>
