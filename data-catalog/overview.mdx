> **85 tables** across 11 categories, available via a readonly ClickHouse account.

The Surf Data Catalog documents all tables available to agents and analysts. Tables are organized into categories and exposed as ClickHouse views in the `agent` and `curated` databases.

## Connection

| Setting | Value |
|---------|-------|
| **Protocol** | ClickHouse HTTP interface (port 8443, TLS) |
| **User** | `agent` (readonly) |
| **Databases** | `agent` (enriched tables), `curated` (analytics views) |
| **Max execution time** | 120s |
| **Max memory** | 16GB |
| **Max result rows** | 1M |

## Quick Start

```sql
-- Top DEX protocols by volume yesterday
SELECT project, sum(amount_usd) AS volume_usd
FROM agent.ethereum_dex_trades
WHERE block_date = today() - 1
GROUP BY project
ORDER BY volume_usd DESC
LIMIT 10
```

<Tip>
Always filter on `block_date` first — it is the partition key for most tables and enables ClickHouse to skip entire partitions.
</Tip>

## Query Best Practices

1. Always filter on block_date — partition pruning is the #1 performance lever
2. Use LIMIT liberally during exploration; remove for final aggregation
3. Pre-filter in CTEs before JOINing — ClickHouse puts RIGHT side into hash table
4. Use IN (SELECT ...) instead of JOIN when you only need existence checks
5. Avoid SELECT * on billion-row tables — project only needed columns
6. For ReplacingMergeTree tables, always use FINAL to get deduplicated rows
7. Date range first, then entity filters — this matches partition layout
8. Use toStartOfWeek/toStartOfMonth for time-series rollups, not GROUP BY toString(block_date)
9. When counting unique addresses, uniq() is faster than count(DISTINCT) and equally accurate
10. For cross-table analysis, filter each table independently in CTEs before joining
11. FINAL syntax: FROM table_name alias FINAL (not FROM table_name FINAL alias). Place FINAL after the alias.
12. ORDER BY index is a prefix index — filtering on column N only works if columns 1..N-1 are also filtered. Check each table's ordering_key.
13. JOINs: put the smaller table on the RIGHT (it becomes the hash table). Check size_class: 'dimension' tables (<1M rows) always go RIGHT.
14. Bloom filter skip indices (listed in skip_indices) enable fast point lookups on non-ORDER-BY columns like address or tx_hash. Use = or IN with literal values — bloom filters don't work with IN (SELECT ...) subqueries.
15. Use LEFT ANY JOIN (not LEFT JOIN) for dimension lookups — it returns at most one match per row, uses less memory, and avoids accidental row duplication. Use it for: erc20 token lookups, market_details enrichment, perp_meta, wallet_profiles.
16. Nullable column hazards: (1) WHERE nullable_col = 'x' silently drops all NULL rows — use ifNull(col, default) if you want NULLs included. (2) sum()/avg() over Nullable columns silently skip NULLs — wrap with ifNull(col, 0) to count them as zero. (3) GROUP BY treats NULL as a distinct group.
17. Outer JOIN NULL handling: ClickHouse defaults to join_use_nulls=1 (non-matching rows produce NULL). Set join_use_nulls=0 to get default type values (0, empty string) instead — saves memory and avoids downstream NULL surprises.

## Entity Linking

Common join patterns across tables:

- `token_address -> symbol: LEFT ANY JOIN agent.ethereum_erc20 ON contract_address = token_bought_address (or token_sold_address). Dimension table — always on RIGHT.`
- `condition_id -> market_question: LEFT ANY JOIN agent.polymarket_market_details ON condition_id. Dimension table — always on RIGHT.`
- `market_ticker -> category: Use curated.kalshi_daily_categorized (pre-joined with categories, no JOIN needed).`
- `coin -> max_leverage: LEFT ANY JOIN agent.hyperliquid_perp_meta ON coin. Dimension table — always on RIGHT.`
- `project + version -> TVL: LEFT ANY JOIN agent.ethereum_tvl_daily ON (project, version, block_date). Filter TVL table by date range in CTE first.`
- `address -> wallet_label: LEFT ANY JOIN agent.polymarket_wallet_profiles ON address. Dimension table.`
- `address -> is_smart_money: LEFT ANY JOIN agent.polymarket_smart_money_wallets ON address. Dimension table — 500 rows.`
